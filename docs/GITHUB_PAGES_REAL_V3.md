# การเปิด Frontend V3 ตัวจริงบน GitHub Pages — 19 พฤศจิกายน 2569

## จุดประสงค์

ผู้เข้าร่วมประชุมทดลอง **หน้าจอ Frontend V3 ตัวจริง** (ไม่ใช่ตัวสาธิตแบบย่อ)
เพื่อค้นหารหัส **TCNP v1.8** และทดลองลำดับงานการพยาบาลด้วยข้อมูลผู้ป่วยสมมติเท่านั้น

## การตั้งค่า GitHub Pages

Repository `witsaoo-jpg/TCNP` → **Settings → Pages** → Source:
**Deploy from a branch** → Branch **`gh-pages`** → Folder **`/(root)`** → **Save**.

ตรวจ GitHub Pages ขึ้น `Your site is live` ก่อนทดลองลิงก์
`https://witsaoo-jpg.github.io/TCNP/` (ก่อนขึ้นสถานะนี้ อาจยังเป็น 404)

## แนวทางทดลองจริง

1. เปิดหน้า Login ของ Frontend V3 ผ่าน URL ด้านบน
2. กด **เข้าทดลอง Frontend V3 (ไม่ต้องใช้รหัสผ่าน)**
3. เลือกวอร์ด เช่น `34` (เคมีบำบัด) หรือวอร์ดอื่นจากรายการเดิม
4. เลือกผู้ป่วยสมมติ `DEMO-*`
5. ไปที่ Nursing Note → สร้างปัญหา → ค้นหารหัส TCNP ตามส่วน F/A/G/I/E
6. ทดลองบันทึก Draft → ตรวจ/แก้ไข → SIGNED จำลอง → Addendum → Care Summary
7. ทดลองใช้เมนู TCNP Master ของ Admin สำหรับค้นหา F และ P (หน้าจอ Admin บางฟังก์ชันต้องมี backend จึงใช้ไม่ได้ใน Pages)
8. หลังทดลอง กดปุ่มสีเหลือง **ล้างข้อมูลทดลอง**

## ข้อจำกัดสำคัญ

- เว็บไซต์นี้ **ไม่มีระบบ Login / RBAC / RLS จริง**: ผู้เข้าร่วมกดปุ่ม Demo แล้วเข้าได้ทันที
- การลงนามและประวัติเป็น **การจำลองในเบราว์เซอร์** ไม่ใช่การบันทึกทางการแพทย์
- ข้อมูลทดลองจะเก็บใน `localStorage` **เฉพาะเบราว์เซอร์/อุปกรณ์ที่ใช้อยู่** และไม่ซิงก์กับเครื่องผู้อื่น
- **ห้าม** กรอกข้อมูลผู้ป่วยจริง ชื่อ HN/AN เบอร์โทร ประวัติการรักษา หรือรหัสผ่านจริง
- ฟังก์ชันที่อาศัย API โรงพยาบาล เช่น การพิสูจน์ตัวตน, audit ที่รับรอง, Analytics จริง, งาน admin บางส่วน จะยังไม่ทำงานสมบูรณ์
- TCNP v1.8 และคำศัพท์วิชาชีพต้องตรวจสอบสิทธิ์เผยแพร่จากเจ้าของข้อมูลก่อนแจกจ่ายสาธารณะ

## หลังจบงาน

ปิด Pages ที่ Settings → Pages หรือเปลี่ยน Source กลับตามนโยบายหน่วยงาน
และลบข้อมูลในเบราว์เซอร์ที่ใช้ทดสอบ ไม่ต้องลบโค้ดต้นฉบับสำหรับพัฒนาต่อ
**คำเตือน:** ปิด Pages/ลบ Branch ไม่ได้ลบข้อมูลที่เคย Push ออกจากประวัติ GitHub

## นำเข้าระบบโรงพยาบาล

การนำไปใช้จริงต้องสลับ `ENR_CONFIG.USE_MOCK_DATA` เป็น `false`
และเชื่อมต่อ Backend Node.js/Express, PostgreSQL, server-side sessions, RBAC/RLS, audit,
การลงนาม และมาตรการข้อมูลสุขภาพภายใต้การอนุมัติของโรงพยาบาล
โดย **ห้าม** นำโหมด LocalStorage ไปบันทึกข้อมูลผู้ป่วยจริง
